Part 1 / What it is

Assistant + agent + platform.

ASSISTANT

Helps you think and create

Completes, explains, drafts, transforms, and keeps you in flow.

AGENT

Works through a task

Plans, edits, runs tools, verifies, and iterates toward an outcome.

PLATFORM

Connects the system

Models, context, tools, policies, customizations, workflows, and agents.

The interface changes. The human responsibility does not: you define the outcome and decide what is ready.

Timing: 4 minutes

Use all three frames. Completions and chat are assistant interactions. Agent workflows take multi-step action. The platform frame explains models, tools, context, governance, and extensibility.

Part 1 / The shift

From predicting code to coordinating work.

  1. 2021Complete

    Predict the next line or block.

  2. 2023Chat

    Explain, transform, and answer in context.

  3. 2024Choice

    More models, context, and customization.

  4. 2025Agents

    Plan, edit, run tools, and open pull requests.

  5. 2026Workflows

    Projects, connected tools, orchestration, and automations.

The useful question changed from “What code can it suggest?” to “What outcome can we safely move forward?”

Timing: 4 minutes

Do not spend time on every release. Explain the conceptual shift: suggestion, conversation, agency, and coordinated workflows. Human accountability remains constant.

Part 1 / Multi-model

Choose a model — or let Copilot route the work.

Copilot supports model choice across multiple providers. The useful choice is not always a model name; it can be the routing strategy and effort level.

  • Direct selectionChoose an enabled model when you want a specific capability or behavior.
  • Copilot FusionRoutes or orchestrates enabled models using single, cascade, or critique patterns.
  • Effort levelsStandard, High, and Max trade speed, cost, and depth.
  • Local modelsExperimental routing is available on supported clients and devices.
OpenAIAnthropicGoogleLocal where supported
Timing: 5 minutes

Avoid reading a static model catalog. Explain direct model choice, model policies, Fusion routing and orchestration, effort levels, and experimental local-model routing. Availability depends on client, plan, policy, and hardware.

Part 1 / Where it lives

One Copilot. Different surfaces for different work.

IDE

Completions, chat, plan, agents, tests, review, and local tools.

GitHub.com

Issues, pull requests, code review, repositories, and cloud agents.

CLI

Terminal-native sessions with local files, GitHub, MCPs, skills, and tools.

Copilot app + mobile

Projects, sessions, delegation, connected context, review, and cross-client continuity.

Choose the surface where the context is strongest and the result is easiest to review. Sessions can increasingly continue across clients.

Timing: 4 minutes

Explain that surfaces do not necessarily have identical tools or permissions. IDE is strongest for tight code loops, GitHub.com for repository collaboration, CLI for terminal and connected context, and the app for longer session-oriented work.

Part 1 / Choose the mode

Use only as much autonomy as the task needs.

  1. 1
    CompleteSuggest the next code or edit
  2. 2
    AskExplain, locate, compare, or draft
  3. 3
    PlanExplore and agree on the route
  4. 4
    AgentEdit, run, verify, and iterate
  5. 5
    Delegate / automateBounded asynchronous or recurring work

More autonomy increases the value of clear scope, explicit constraints, checkpoints, and evidence.

Timing: 4 minutes

Give one simple example for each level. Explain that Plan is valuable when scope is uncertain, while delegation is strongest for bounded tasks with clear acceptance criteria and good feedback.

Part 1 / Agents + workflows

Agents do the task. Workflows keep it moving.

CODING AGENT · BOUNDED TASK
  1. UnderstandRead the issue, repository instructions, code, and history.
  2. ImplementCreate a branch, edit files, run tools and tests, and iterate.
  3. ProposeOpen a pull request with the change, evidence, and remaining risk.
  4. ReviewCopilot code review inspects the diff and suggests fixes; a human validates the feedback.
CHOOSE WHERE THE SESSION RUNS
Local sandbox

Runs on your machine with operating-system restrictions on agent tool access to files, network, and credentials.

Cloud sandbox

Runs the whole session in an isolated GitHub-hosted environment that you can steer across clients.

GitHub Actions

Runs repository-scoped work in a configured Actions development environment.

WORKFLOW EXAMPLE Pull request opened→Copilot code review→Agent Merge fixes selected blockers→Human approves and merges

Agent sessions and sandboxes · Copilot code review · Agent Merge

Timing: 5 minutes

Explain the difference between a bounded coding-agent task and a repeatable workflow. Local sandboxing restricts tool access on the user's machine; a cloud sandbox runs the whole session in a GitHub-hosted environment; Actions is a repository-scoped environment. Copilot code review provides suggestions on the pull request, but its feedback still needs validation. Use Agent Merge as the workflow example: it watches selected pull request blockers and works on them, while a person owns the final merge.

Part 1 / Working model

Start with a real question. Keep the evidence visible.

  1. 01QuestionState the outcome
  2. 02ContextRetrieve useful sources
  3. 03ActionDraft, change, review, or task
  4. 04EvidenceSources, checks, and diff
  5. 05DecisionPublish, delegate, ask, or stop
Prompt contract Inspect [scope]. Produce [outcome]. Preserve [boundaries]. Verify with [evidence]. Stop before [approval point].
Timing: 4 minutes

Repeat this workflow during the demo. The prompt contract makes the finish line checkable: scope, outcome, boundaries, evidence, and an approval point. The action can be code, an issue, a review, a decision record, or a clear next step.

Part 1 / What is new

The unit of work is getting bigger than a chat session.

  • ProjectsKeep repositories, notes, designs, connected tools, agents, and results together.
  • Workflows + automationsMake stable processes repeatable, observable, and shareable with a team.
  • Cross-client sessionsStart, steer, and review work across VS Code, the app, CLI, GitHub.com, and mobile.
  • Computer use + sandboxingExpand the tools agents can use while defining stronger local execution boundaries.

Snapshot: 30 October 2026. Preview and rollout status varies.

Timing: 5 minutes

Focus on the direction of travel: projects organize larger goals, workflows and automations make processes repeatable, sessions move across clients, and computer use broadens the execution surface. Treat all status as dated.

Part 1 / Example use cases

Copilot is useful before, during, and after coding.

UNDERSTAND

Unfamiliar work

Explain a repository, initiative, acronym, team, code path, or historical decision with sources.

PREPARE

Meetings and the day

Connect calendar, documents, Slack, people, and GitHub activity into a focused briefing.

CREATE

Conversation to contribution

Turn a decision into an issue, pull request description, documentation change, or next action.

BUILD

Repository tasks

Plan, implement, test, and review a bounded change using repository instructions.

INVESTIGATE

Failures and incidents

Trace Actions failures, logs, code, deployments, and operational context.

REPEAT

Workflows and automations

Schedule dependable summaries, checks, triage, or repository routines.

Timing: 4 minutes

Choose only a few examples that match the audience. The point is breadth across roles, not an exhaustive catalog.

Part 1 / Responsible use

Copilot can accelerate judgment. It cannot replace accountability.

01

Use appropriate context

Do not include secrets, credentials, customer data, or unnecessarily sensitive personal information.

02

Inspect the sources

Check dates, authors, ownership, permissions, relevance, and conflicting guidance.

03

Review before acting

Inspect generated content, commands, diffs, tests, audience, and user-visible impact.

04

Route accountable decisions

Policy, legal, HR, security, access, and people decisions need the official system or owner.

Timing: 3 minutes

Avoid absolute statements about what Copilot can see, retain, or access. Those answers depend on the feature, configuration, surface, and policy.
