Welcome everyone. This is a practical orientation, not a feature inventory. The goal is to leave with a mental model, a repeatable control loop, and enough confidence to choose the right Copilot workflow for a task.

Set the theme early: Copilot can suggest, plan, and act, but the human remains accountable for intent, judgment, and the final result.

04 / Choose the mode

Climb only as high as the task needs.

  1. 1
    CompletePredict the next code or edit
  2. 2
    AskExplain, compare, locate, draft
  3. 3
    PlanExplore and propose before editing
  4. 4
    AgentEdit, run, verify, iterate locally
  5. 5
    Cloud agentWork asynchronously on an isolated branch

Rule: use the least autonomy that solves the task.

Timing: 3 minutes

Completion fits a change you already understand. Ask is strong for learning. Plan is valuable when scope is uncertain. Agent mode fits an approved implementation. The cloud agent fits bounded asynchronous work reviewed through a branch or pull request.

More autonomy is not automatically better. It increases the value of explicit constraints, acceptance criteria, and verification.

06 / Get better results

Specific does not mean long. It means testable.

Context+Intent+Constraints+Feedback
Reusable prompt pattern
Inspect [scope]. Produce [outcome]. Preserve [constraints]. Verify with [checks].

Vague "Add CSV export."

Bounded Add --format csv; preserve JSON default and API; no dependency; RFC 4180 edge tests; run targeted checks; summarize risks.

Timing: 2 minutes

A prompt is a lightweight specification plus a feedback loop. Context narrows what matters, intent defines the result, constraints preserve behavior, and feedback helps the next iteration converge.

Contrast the vague request with a bounded one. The second prompt gives Copilot a finish line and gives the human a review checklist.

07 / Delegation

Pair in the foreground. Delegate in the background.

Local agent

Fast feedback, shared attention

  • You watch the work unfold
  • Approvals happen in context
  • Best for exploration and tight iteration
Foreground pairing
VS
Copilot cloud agent

Bounded work, asynchronous review

  • Works on an isolated branch
  • You review evidence and diff later
  • Best for clear, testable outcomes
Background delegation

Sweet spot Bounded work + good tests + clear acceptance criteria

Timing: 2 minutes

Local and cloud agents are complementary. Stay local when learning the code, making frequent decisions, or handling an uncertain task. Delegate when the objective is bounded and the repository can provide fast evidence through tests and checks.

An isolated branch reduces collision; it does not remove the need to review. Branch protections, required checks, and human approval remain part of the workflow.

  3. 03Verify

    Tests and checks create evidence.

  4. 04Review

    You inspect the diff and iterate.

  5. 05Merge

    Your protections and approvals still apply.

Sweet spot Bounded work + good tests + clear acceptance criteria

Timing: 2 minutes

The cloud agent can research, plan, change code on an isolated branch, and open a pull request. It is strongest when the task is bounded and the repository has fast feedback.

Isolation reduces collision; it does not make the result correct. Branch protection, required checks, approvals, and human review remain part of the workflow.

Timing: 2 minutes

Generation is only one step. Verification should use the smallest relevant check first, then broaden if risk warrants it. Review the actual diff, not just the agent's summary.

Code review now offers generally available Lite and Balanced effort levels. Match review depth to change risk, then validate each finding yourself. A passing suite does not prove the requirement is right.

11 / Trust + governance

Guardrails are shared infrastructure.

Organization controls

  • Policy and feature settings
  • Content exclusion
  • Public code matching controls
  • Audit and usage visibility
  • Approval boundaries

Your responsibilities

  • Never paste secrets
  • Inspect references and provenance
  • Review commands before approval
  • Validate output for the real context
  • Escalate policy questions

Avoid absolutes about what Copilot can see, retain, or access. The answer depends on feature, configuration, and policy.

Timing: 2 minutes

Trust is not one setting. It is a system of product controls, organization policy, repository protections, and user behavior. Mention content exclusion, public code matching, audit and usage visibility, and approvals without implying every control applies identically to every feature.

User responsibilities remain: do not submit secrets, inspect referenced material, review tool calls and commands, and validate the result in its deployment context. Point policy-specific questions to the appropriate internal owner or current official documentation.

13 / Live demo

Show the control loop, not a magic trick.

2:00

Ask

"Explain report flow, find tests, recommend safest files. Cite paths."

2:00

Plan

"Plan CSV; preserve JSON; no dependency; RFC 4180; edge tests. Wait."

5:00

Agent

"Implement approved plan. Targeted tests first, then smallest broader check."

2:00

Review

"Review current diff. Rank findings. Do not edit yet."

Backup ready: before/after branch or 60-90 second recording. Never debug live.
Timing: 12 minutes

Setup - 1 minute: Tiny CLI repo, fast tests, report command defaults to JSON. We add CSV without breaking the contract.

Ask - 2 minutes: "I'm a new contributor. Explain the command flow for reports, identify tests, and recommend the safest files for adding another output format. Cite files."

Plan - 2 minutes: Ask for --format csv, JSON default preserved, no dependency, RFC 4180 quoting, edge-case tests, API compatibility, and approval before edits.

Agent - 5 minutes: Approve the plan. Ask for targeted tests first, the smallest broader check, and a summary of changed files, evidence, and risks.

Review - 2 minutes: Ask Copilot to review only the current diff for correctness, RFC 4180 edge cases, backward compatibility, and security; rank findings and do not edit yet.

If the environment, network, or model stalls, switch immediately to the prepared branch or short recording. Narrate the same control loop. Do not troubleshoot in front of the room.

14 / Start small

Five habits for your first week.

  1. 01

    Orient in one unfamiliar repository.

  2. 02

    Use Plan once before editing.

  3. 03

    Add one useful repository instruction.

  4. 04

    Request one Copilot review - then challenge it.

  5. 05

    Share one workflow that actually helped.

Build judgment through small, observable loops.

Timing: 2 minutes

Make adoption concrete and low pressure. The goal is not maximum Copilot usage. It is learning where it helps, how to constrain it, and how to evaluate its work.

Challenge a review suggestion on purpose: ask for evidence, inspect the cited code, and decide whether the finding matters. Share useful workflows so team practice compounds.
